# AI利用量ブレーカーの開発者例外

この機能は `unknown_usage_breaker` の拒否だけに適用される。認証済み user ID をバックエンドが既存の claim RPC に渡し、同時に1アカウントだけを許可する。`ai_quota_backend` は信頼されたサーバー専用資格情報であり、任意の user ID を渡せるため、クライアントに渡してはいけない。APIロールとReaderは設定を変更できない。

例外は開始時刻以上・終了時刻未満、最大24時間、最大5回。ブレーカー発動時に限り使用し、緊急停止・日次・同時実行・月次費用制限を通過して通常リクエストが予約されたときに1回消費する。失敗・利用量不明でも返却しない。通常の試行と同様に記録・計測し、不明なら `unknown_usage` にする。未設定、期限外、使い切りは拒否する。通常ユーザーとブレーカー非発動時の挙動は変わらない。

## 承認と設定

新 migration のマージや適用だけでは例外は有効にならない。Dev・ProdそれぞれでReaderによる移行計画を確認し、別途承認された既存Writer手順で適用する。現在のWriter設定・Environment保護を変えず、PENDINGの実適用は未検証。アプリの本番ゲートはshared履歴が `IN_SYNC` になるまで停止する。既存の本番・開発DBに対する設定操作はそれぞれ別途承認を要する。

設定・監査は権限を持つ管理者の承認済み経路で行う。既存Readerは設定の詳細や利用記録を読めず、アプリのDBロールは直接テーブルを変更できない。権限昇格や新たな資格情報の作成をこの機能の一部として行わない。管理者は本人確認済みのSupabase user ID、期間、回数、承認記録を確認し、設定を単一トランザクションで変更する。例を示すが、本番への実行は別途承認なしに行わない。

- **有効化:** 未設定・失効状態を確認し、`developer_user_id`、`developer_valid_from`、`developer_expires_at`、`developer_max_uses`、`developer_used_count = 0` を同時に設定する。開始から終了は24時間以内、回数は1〜5。現在有効な許可を上書きしない。
- **失効:** 終了時刻で自動的に無効になる。明示的な取り消しは5列すべてを同時に `NULL` にする。既存の利用履歴は削除しない。
- **再許可:** 前回の使用状況と不明利用を確認し、新しい明示承認に基づき5列を原子的に再設定して使用回数を0にする。自動更新・自動再許可はしない。
- **緊急停止:** 従来の `ai_quota.settings.emergency_stop` が例外より優先され、全ての新規 AI claim を拒否する。停止や解除は別途承認済みの管理者手順で行う。例外だけを止める場合は5列を消去する。

不明利用が解決しない場合、例外を繰り返し再許可して安全装置を実質的に無効化しない。実測値のない利用を推定値やゼロとして精算しない。アカウント削除時は許可を取り消す。例外を使った請求額が不明な場合、既存の実測月額上限はその費用を保証しない。
